# Pocket Kinship 기획서

## 1. 개요

- 장르: 퍼즐 (인접 제약 충족형)
- 목표: 보드의 모든 노드에, 주어진 포켓몬 리스트를 전부 배치한다.
- 리스트의 포켓몬 수는 항상 노드 수와 같다 (모든 난이도 공통).

## 2. 핵심 룰

1. 빈 노드에 포켓몬을 배치한다.
2. 배치 시점에, 이미 채워진 인접 노드 각각과 공통 속성이 최소 1개 있어야 한다.
   - 공통 속성은 "같은 카테고리의 같은 값"을 말한다 (예: 둘 다 불꽃 타입).
   - 인접 노드마다 매칭에 쓰는 카테고리는 달라도 된다.
   - 인접 노드 중 하나라도 공통 속성이 없으면 그 선은 이어지지 않는다. 그래도 포켓몬은 그 자리에 놓이고, 이어질 수 없는 선이 빨간색 `연결 불가`로 표시된다. 자동으로 회수되지 않으며, 플레이어가 직접 회수하거나 옮겨야 한다.
   - Expert와 Master 난이도는 인접한 두 노드가 서로 다른 카테고리 2개 이상에서 공통 속성을 가져야 한다. (같은 카테고리에서 값 2개가 겹쳐도 1개로 센다.)
3. 해당 사항이 없는 카테고리끼리(예: 둘 다 전용기 없음, 둘 다 네임드 트레이너 없음)는 매칭으로 인정하지 않는다.
4. 매칭 검사는 배치하는 순간에만 한다. 이후 이웃이 빠져도 이미 놓인 포켓몬은 유지된다.
5. 모든 노드를 채우면 클리어.

## 3. 회수

- 배치한 포켓몬은 노드 순서와 무관하게 자유롭게 회수할 수 있다.
- 연쇄 회수는 없다. 회수한 노드의 이웃은 그대로 남는다.
- 회수한 포켓몬은 대기 리스트로 돌아간다.
- 초기화 버튼: 보드 전체를 한 번에 회수한다.
- 횟수 제한은 없고, 회수 횟수만 카운트한다.
  - 개별 회수 1번 = 1회
  - 초기화 1번 = 1회 (몇 개가 놓여 있었는지와 무관)

## 4. 등급 (회수 횟수 기준)

| 회수 횟수 | 등급 |
|---|---|
| 0 | S |
| 1~2 | A |
| 3~5 | B |
| 6~10 | C |
| 11 이상 | F |

- 원안은 "6~10 C / 10+ F"로 10이 겹쳐서, 11 이상을 F로 해석했다. (확인 필요)
- 보드 크기(5/7/9)와 난이도에 관계없이 같은 기준을 쓴다.

## 5. 공통 속성 카테고리

| 카테고리 | 가능한 값 | 비고 |
|---|---|---|
| 타입 | 노말, 불꽃, 물, 전기, 풀, 얼음, 격투, 독, 땅, 비행, 에스퍼, 벌레, 바위, 고스트, 드래곤, 악, 강철, 페어리 (18) | 복수 타입 중 1개만 겹쳐도 인정 |
| 진화할 방법 | 친밀도, 진화의 돌, 교환, 시간, 장소, 성별, 기술 습득, 파티 조건, 아이템 지참, 특수 행동 | 이 포켓몬이 다음 형태로 진화할 때 쓰는 방법. 아래 세부 규칙 참고 |
| 진화한 방법 | 친밀도, 진화의 돌, 교환, 시간, 장소, 성별, 기술 습득, 파티 조건, 아이템 지참, 특수 행동 | 이 포켓몬이 되기 위해 앞 형태가 쓴 방법. 값 목록은 진화할 방법과 동일 |
| 4배 약점 타입 | 18개 타입 | 없는 포켓몬은 해당 없음 |
| 1/4 반감 타입 | 18개 타입 | 없는 포켓몬은 해당 없음 |
| 사용한 네임드 트레이너 | 챔피언, 사천왕, 관장, 보스가 사용한 트레이너 개인 | 범위는 이 4개 역할까지만. 없는 포켓몬은 해당 없음 |
| 등장 세대 | 1~9세대 (첫 등장 기준) | |
| 보유 폼 | 메가진화, 거다이맥스, 원시회귀, 테라스탈폼, 리전폼 보유, 리전폼 자체 | 아래 세부 규칙 참고. 없는 포켓몬은 해당 없음 |
| 전용기 | 전용기 보유 | 기술 이름은 보지 않는다. 없으면 해당 없음 |
| 전용 Z기술 | 전용 Z기술 보유 | 기술 이름은 보지 않는다. 전용기와 별도 카테고리 |
| 보유 특성 | 특성 이름 (약 300종) | 복수 특성 중 1개만 겹쳐도 인정 |
| 특수 분류 | 포지션(스타팅, 준전설, 초전설, 환상, 울트라비스트, 패러독스) 다음에 독특한 성비(수컷 100%, 암컷 100%, 무성) | 두 가지를 한 카테고리로 합쳤다. 어느 쪽이든 하나만 겹치면 인정하고 카테고리 1개로 센다. 일반 성비와 해당 없음은 값이 없다. |

"해당 없음" 값은 매칭에 쓰이지 않는다 (룰 3).

### 진화할 방법 / 진화한 방법 세부 규칙
- 단순 레벨업 진화는 값에서 제외한다 (해당 포켓몬이 너무 많아 변별력이 없음). 레벨업 + 조건 진화만 아래 값으로 잡는다.
- 진화의 돌: 돌 종류와 무관하게 하나의 값.
- 교환: 통신교환과 아이템 지참 교환을 하나의 값으로 묶는다.
- 시간: 낮 진화와 밤 진화는 같은 값.
- 성별: 성별에 따라 진화하는 포켓몬끼리는 같은 값 (수컷/암컷 구분 없음).
- 장소, 기술 습득, 파티 조건, 아이템 지참은 각각 독립된 값.
- 분기 진화 포켓몬처럼 진화 방법이 여러 개면 전부 보유한 것으로 보고, 그중 하나만 겹쳐도 인정.
- 진화하지 않는 포켓몬(진화할 방법), 진화 결과가 아닌 1단계 포켓몬(진화한 방법), 단순 레벨업으로만 진화하는 경우는 해당 없음.

### 보유 폼 세부 규칙
- 리전폼 보유: 리전폼이 존재하는 포켓몬 (지역은 구분하지 않는다).
- 리전폼 자체: 그 포켓몬 자신이 리전폼인 경우.
- 테라스탈폼: 테라파고스, 오거폰처럼 테라스탈 관련 폼이 있는 포켓몬.
- 메가진화, 거다이맥스, 원시회귀: 해당 폼이 있는 포켓몬.

## 6. 보드

보드와 난이도는 별개의 축이다.

### 5노드: 오각형
- 외곽 5개 노드가 순환 연결. 엣지 5개.

### 7노드: 육각형 + 중심
- 외곽 6개 노드가 순환 연결 + 중심 노드가 외곽 6개 전부와 연결. 엣지 12개.

### 9노드: 사각형 + 중점 + 중심
- 모서리 4개와 변 중점 4개가 모서리-중점-모서리 순으로 순환 연결 (엣지 8개).
- 중심 노드는 중점 4개와만 연결 (엣지 4개). 모서리와의 대각선 연결은 없다.
- 총 엣지 12개.

## 7. 난이도

- 4단계: Easy, Super, Expert, Master
- 난이도는 리스트에 포함된 포켓몬들이 서로 공유하는 카테고리의 양을 조절한다.
  - 난이도는 두 축이다. 매칭 조건: Easy·Super는 카테고리 1개 이상, Expert·Master는 서로 다른 카테고리 2개 이상. 정답 수: Easy·Expert는 정답이 많고, Super·Master는 정답이 적다.
  - 따라서 Easy(1개, 정답 많음), Super(1개, 정답 적음), Expert(2개, 정답 많음), Master(2개, 정답 적음).
- 3보드 × 4난이도 = 12개 조합.

## 8. 데이터 스키마

### 원칙
- 카테고리 값은 전부 문자열 배열로 통일한다. 빈 배열은 "해당 없음"이다.
- 매칭 판정은 하나의 공통 함수로 처리한다: 두 포켓몬의 같은 카테고리에서 배열 교집합이 비어 있지 않으면 매칭. 빈 배열은 교집합이 생길 수 없으므로 룰 3(해당 없음끼리 매칭 불가)이 자동으로 지켜진다.
- 값은 영문 슬러그로 저장하고, 화면에 보이는 한글 이름은 별도 라벨 파일에서 가져온다.

### 포켓몬 1마리
```json
{
  "id": "pikachu",
  "dex": 25,
  "name": { "ko": "피카츄", "en": "Pikachu" },
  "attrs": {
    "type": ["electric"],
    "evolveVia": ["stone"],
    "evolvedVia": ["friendship"],
    "weak4x": [],
    "resist4x": [],
    "trainer": ["red"],
    "generation": ["1"],
    "forms": ["gmax"],
    "signatureMove": [],
    "signatureZ": ["has"],
    "abilities": ["static", "lightning-rod"],
    "classification": []
  }
}
```

- 카테고리 키 12개: `type`, `evolveVia`, `evolvedVia`, `weak4x`, `resist4x`, `trainer`, `generation`, `forms`, `signatureMove`, `signatureZ`, `abilities`, `classification`
- `signatureMove`, `signatureZ`: 보유하면 `["has"]`, 없으면 `[]`.
- `forms` 값: `mega`, `gmax`, `primal`, `terastal`, `regional-has`, `regional-self`.
- `classification` 값: 포지션 `starter`, `sub-legendary`, `legendary`, `mythical`, `ultra-beast`, `paradox` 다음에 성비 `male-only`, `female-only`, `genderless`.
- `trainer` 값은 영문 이름이고, 화면에 보이는 한국어 이름은 `categories.json`의 라벨(`data/trainer-names.json`에서 온다)을 쓴다.
- 리전폼 포켓몬(알로라 라이츄 등)은 별도 항목으로 만든다. 메가, 거다이맥스 등은 항목이 아니라 `forms` 값으로만 존재한다.

### 파일 구성
```
pocket-kinship/data/
├── categories.json   # 12개 카테고리와 각 값의 한글 라벨 (자동 생성)
├── pokemon.json      # 포켓몬 전체 (위 구조의 배열, 자동 생성)
├── trainer-names.json    # 트레이너 한국어 이름 (scripts/fetch-trainer-names.mjs 로 Bulbapedia 에서 수집)
├── signature-moves.json  # 전용기 후보와 배울 수 있는 포켓몬 (검토용, 자동 생성)
└── overrides.json    # 수동 입력분: position 목록, signatureMove/signatureZ 목록, trainer
pocket-kinship/scripts/build-data.mjs   # PokéAPI + overrides.json -> 위 두 파일 생성
```

- 실행: `node scripts/build-data.mjs` (API 응답은 `data/.cache/`에 캐시되어 재실행이 빠르다)
- `overrides.json`의 `trainer`는 `{ "트레이너 이름": ["포켓몬 id", ...] }` 형식이고, 이때 트레이너 값은 슬러그가 아니라 표시 이름 그대로 쓴다.
- 스크립트가 알 수 없는 id를 `overrides.json`에서 발견하면 경고를 출력한다.

### 데이터 출처
| 카테고리 | 출처 |
|---|---|
| type, abilities, generation | PokéAPI |
| evolveVia, evolvedVia | PokéAPI 진화 체인에서 계산 |
| weak4x, resist4x | 타입 상성표로 계산 |
| forms | PokéAPI 폼 정보 + 일부 수동 보정 |
| trainer, signatureMove, signatureZ | 수동 입력 (PokéAPI에 없음) |
| classification | 포지션은 PokéAPI 전설/환상 표시에 수동 목록을 더하고, 성비는 PokéAPI |

수집 스크립트가 PokéAPI 값을 채운 뒤 `overrides.json`을 덮어써서 `pokemon.json`을 만든다.

## 10. 리스트 생성 알고리즘 (초안)

### 문제 정의
- 보드 그래프의 모든 엣지에서 두 노드의 포켓몬이 매칭 조건(공통 카테고리 k개 이상, Expert·Master는 k=2, Easy·Super는 k=1)을 만족하도록 N마리를 노드에 하나씩 배치하는 것이 정답이다.
- 배치와 회수가 자유로우므로 순서는 상관없다. 최종 배치에서 모든 엣지가 조건을 만족하면 항상 그 순서로 채울 수 있다.

### 생성 절차
1. 사전 계산: 1079마리 쌍마다 공통 카테고리 수를 계산해 두 개의 인접 목록(k≥1, k≥2)으로 저장한다.
2. 정답 심기: 노드를 무작위 순서로 훑으며, 이미 놓은 이웃과 전부 매칭되고 중복되지 않는 포켓몬을 뽑아 배치한다. 막히면 처음부터 다시 한다. 이렇게 만든 배치가 정답이라 해의 존재가 보장된다.
3. 검증: 뽑힌 N마리로 백트래킹해서 정답 개수를 센다. 보드의 대칭(오각형 10, 육각형 12, 사각형 8가지 등)만 다른 배치는 같은 해로 본다.
4. 난이도 판정: 정답 개수, 뽑힌 N마리 사이의 매칭 밀도(가능한 쌍 중 매칭되는 쌍의 비율)로 난이도 구간을 판정한다. 구간에 안 맞으면 2번부터 다시 뽑는다.
5. 구간 경계값은 각 난이도로 수천 번 생성해 분포를 본 뒤 정한다.

### 실행 방식
- 미리 생성: 보드 3종 × 난이도 4단계 조합마다 퍼즐을 여러 개 만들어 JSON으로 저장한다. 실행 중에는 저장분을 고르기만 한다.
- 실행: `node scripts/generate-puzzles.mjs [--count 30] [--seed 1]` → `data/puzzles.json` (기본 보드×난이도×범위마다 30개)
- `node scripts/generate-puzzles.mjs --explore`: 난이도 설정별 정답 개수 분포를 출력한다 (구간 경계값 조정용)
- 보드 정의는 `data/boards.json` (노드 번호와 엣지). 오각형 0~4, 육각형 0~5 외곽 + 6 중심, 사각형 0~7 외곽(모서리·중점 번갈아) + 8 중심.

### 난이도 판정 (정답 종류 수, 보드 대칭 제외)
| 난이도 | 매칭 기준 | 인접하지 않은 쌍 | 정답 종류 |
|---|---|---|---|
| Easy | 카테고리 1개 이상 | 제약 없음 (정답 많게) | 오각형 4+, 육각형 20+, 사각형 100+ |
| Super | 카테고리 1개 이상 | 35% 확률로 매칭 금지 (정답 적게) | 오각형 1~3, 육각형 1~8, 사각형 1~12 |
| Expert | 카테고리 2개 이상 | 제약 없음 (정답 많게) | 오각형 4+, 육각형 9+, 사각형 13+ (Master 상한 바로 위) |
| Master | 카테고리 2개 이상 | 50% 확률로 매칭 금지 (정답 적게) | 오각형 1~3, 육각형 1~8, 사각형 1~12 |

보드마다 가능한 정답 종류의 최대치가 달라서(오각형 12, 육각형 420, 사각형 45360) 구간은 보드별로 다르게 잡았다. 정답 종류 1은 정답이 하나뿐인 퍼즐이다.

### 세대별 퍼즐
- 범위(scope)가 1~9이면 그 세대 포켓몬(리전폼 포함)만 후보로 쓴다. 전체 퍼즐은 scope가 `all`.
- 세대별 퍼즐에서는 등장 세대 카테고리를 매칭 계산에서 뺀다 (전부 같은 값이라 의미가 없으므로).
- 후보가 적은 6세대는 Expert·Master(카테고리 2개)가 모자란다 (오각형 Expert 23/30, 육각형 Expert·Master 4/30, 사각형 Expert 2/30·Master 5/30). 정답 수 구간이 아니라 후보 수의 한계다: 카테고리 2개씩 겹치는 6세대 조합 자체가 몇 개 없다.. 나머지 조합은 30개씩 채워진다.

### 검증
- 생성 후 원본 데이터로 정답 배치가 규칙(엣지마다 공통 카테고리 k개 이상, 중복 없음, 범위 일치)을 지키는지 다시 확인한다. 위반하면 스크립트가 오류로 멈춘다.

## 11. 앱 구성 (Vite + React)

- 실행: `npm run dev` (개발), `npm run build` (빌드). 데이터 재생성은 `npm run data`, `npm run puzzles`.
- `src/game.js`: 데이터 로드, 매칭 계산(`sharedCats`), 등급(`grade`), 보드 좌표(`LAYOUT`)
- `src/App.jsx`: 메뉴 (범위·보드·난이도 선택) 와 퍼즐 선택
- `src/Game.jsx`: 보드, 포켓몬 트레이, 상세 패널, 회수·초기화, 클리어 화면
- 조작: 아래 트레이에서 포켓몬을 고르고 빈 노드를 누르면 배치. 놓인 노드를 누르면 상세 패널이 열리고 거기서 회수. 초기화는 상단 버튼.
- 배치 규칙을 어기면 이유를 메시지로 보여주고 배치하지 않는다.
- 스프라이트는 PokéAPI sprites 저장소의 이미지를 URL로 직접 불러온다.
- 드래그 조작 (마우스·터치 공통): 트레이의 포켓몬을 빈 노드로 끌면 배치, 놓인 포켓몬을 다른 노드로 끌면 이동(채워진 노드면 서로 교환), 보드 밖으로 끌어내면 회수. 클릭 조작도 그대로 된다.
- 회수 카운트: 회수 1회, 이동·교환 1회, 초기화 1회. 규칙에 어긋난 자리에 놓는 것 자체는 카운트하지 않고, 그 포켓몬을 직접 회수하거나 옮길 때 센다.
- 클리어 조건: 모든 노드가 채워져 있고, 이어진 모든 선이 규칙을 만족해야 한다. 노드를 다 채웠어도 `연결 불가` 선이 하나라도 있으면 클리어되지 않는다.
- 다국어: 한국어/영어. `src/i18n.js`에 화면 문구를 두 벌로 두고, 처음에는 브라우저 언어(`ko`면 한국어, 그 외 영어)로 정한다. 메뉴와 게임 화면의 언어 버튼으로 바꾸면 `localStorage`에 저장된다. 포켓몬 이름은 `name.ko` / `name.en`, 카테고리 이름은 `label.ko` / `label.en`을 쓴다. 카테고리 값(타입, 특성 등)의 영어 라벨은 아직 없다 (화면에 값이 나오지 않는다).
- 게임 이름: 영어 `Pocket Kinship`, 한국어 `포켓 끼리끼리`.
- 연결 설명: 두 노드가 규칙을 만족해 초록 선이 되면, 선 위·아래에 공통점을 문장으로 띄운다 (예: `불꽃 타입`, `얼음에 4배 약점`, `진화 없음`, `3단계 중 2번째`, `초전설`, `메가진화 있음`). 초록 선마다 항상 표시한다. 한 선에 4줄까지 보이고 넘치면 `+n`으로 줄이며, 선에 마우스를 올리면 전체가 툴팁으로 나온다.
- 카테고리 설명: 메뉴와 게임 화면 상단의 `카테고리 설명` 버튼에 마우스를 올리면 큰 창이 뜨고 (눌러서 고정, `닫기`로 닫기도 가능), 12개 카테고리의 설명과 가능한 값을 보여준다. 특성은 종류가 많아 개수만, 트레이너는 전체 이름을 보여준다. Expert·Master나 세대별 퍼즐이면 그 규칙 안내가 함께 나오고, 세대별 퍼즐에서는 등장 세대 항목이 흐리게 표시된다.
- 클리어 화면: 전체 화면 팝업 대신 오른쪽(모바일은 아래) 팀 패널 안에 등급, 회수 횟수, `메뉴`, `다음 퍼즐` 버튼을 띄운다. 마지막 노드를 놓은 뒤에도 보드의 연결 설명을 그대로 볼 수 있다.
- 진화 방식(몇 단계 중 몇 번째)은 카테고리에서 뺐다. 카테고리를 줄여 Master(카테고리 2개 필요)에서 후보 조합이 줄었으므로, 후보가 적은 세대별 Master 퍼즐은 개수가 모자란다.
- 난이도 개편: Expert도 카테고리 2개가 필요하고, Master는 정답을 하나로 좁히지 않고 "정답이 적게" 나오도록 완화했다. Super는 정답이 적은 퍼즐로 바뀌었다 (Expert의 "정답 하나" 조건이 사라짐).
- 첫 화면 인트로: 처음 열면 로고와 소개 문구가 화면 가운데에 크게 나오고 설정 카드는 숨겨져 있다. 약 1.8초 뒤(또는 화면을 누르면 바로) 로고와 문구가 작아지면서 설정·시작 카드가 아래에서 나타난다. 메뉴로 돌아올 때는 다시 재생하지 않고, 모션 줄이기 설정(`prefers-reduced-motion`)이면 인트로 없이 바로 설정 화면을 보여준다.
- 퍼즐 생성 시 모든 포켓몬 쌍이 서로 이어지는 리스트(어떻게 놓아도 정답인 퀴즈)는 뺀다. 생성 후 원본 데이터로 다시 확인해 남아 있지 않음을 검증했다. 이 조건 때문에 오각형은 Easy·Expert의 정답 종류가 4~6개로 줄었고, 6세대 오각형 Expert는 10/30개다.
- 세로가 짧은 PC 창(높이 740px 이하)에서는 메뉴 로고와 여백을 단계적으로 줄인다: 740px 이하는 로고 200px에 설정 제목을 숨기고, 620px 이하는 로고 130px에 부제와 푸터를 숨기고, 520px 이하는 로고 100px에 소개 문구까지 숨겨서 설정이 한 화면에 다 보이게 한다.
- 카테고리 설명 버튼은 생성된 뒤 0.7초가 지나야 호버에 반응한다 (버튼이 막 생겼을 때 마우스가 그 자리에 있어도 설명 창이 저절로 뜨지 않게). 위쪽 버튼에는 등장 애니메이션을 걸지 않는다 (transform/opacity가 걸리면 안의 설명 창이 어긋나고 반투명해진다).
